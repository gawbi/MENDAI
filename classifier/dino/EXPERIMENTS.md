## EX-01 DINOv2 base LoRA 1022

**설계일:** 2026-10-17

**상태:** 12/30 epoch에서 중단 · val 평가 완료

사진 전체를 보는 DINO 분류기가 normal / heel / outsole / both를 얼마나 구분하는지 확인합니다. 향후 YOLO·DETR 및 앙상블과 비교할 첫 기준 실험입니다. 518 입력이나 다른 백본보다 우수하다고 가정하지 않습니다.

**사용자 결정 (2026-10-17):** DINOv2 + LoRA, 1022 입력, 30 epoch. 균형 정확도를 핵심 지표로 하고, 전체 정확도·클래스별 재현율을 함께 봅니다. 출력은 4×4 혼동 행렬과 지표 요약 표입니다.

아래는 설계값과 본 학습에 사용한 설정입니다. 128장 GPU 점검 후 실행 조합을 고정했습니다. 학습 중 설정이 바뀌면 별도 실험으로 구분합니다. 최신 상태와 완료 후 결과는 문서 끝의 실제 실행 기록에 자동 반영됩니다.

## CPU-01 DINOv2 + DINOv3 확률 평균 탐색

**실행일:** 2026-10-18

**상태:** CPU 탐색 완료 · 최종 모델 선택·실험 설정 변경 없음

추가 실험의 우선순위를 판단하기 위해 저장된 안감·밑창 확률을 각각 **50:50 평균하는 한 가지 후보**를 결과 확인 전에 정했습니다. 파일명·정답·데이터 해시를 맞췄고, 기존 실험과 같은 99×99 판정 기준 선택 절차를 사용했습니다. GPU·모델·이미지·test·새 학습은 사용하지 않았습니다. 원래 두 모델의 가중치와 판정 기준도 유지했습니다.

| 후보 | 합산 val 균형 정확도 | 합산 val 전체 정확도 | 신발 그룹 분리 내부 검증 균형 정확도 | 내부 검증 전체 정확도 |
|---|---:|---:|---:|---:|
| DINOv2 | 84.87% | 80.74% | **84.55%** | 80.59% |
| DINOv3 | 84.86% | 81.73% | 83.68% | 80.29% |
| 50:50 평균 | **85.99%** | **83.24%** | 84.54% | **82.41%** |

**내부 검증 방법:** 신발 그룹을 분리한 5-fold `StratifiedGroupKFold`, seed 0. 네 fold에서 판정 기준을 고르고 남은 fold에 적용한 예측을 모아 합산 지표를 계산했습니다. 모델을 재학습하지 않았고 원본 데이터 분할도 바꾸지 않았습니다. 원래 모델 개발에는 전체 val을 사용했으므로 독립적인 최종 평가나 모델 전체의 교차검증으로 해석하지 않습니다.

**해석:** 평균 후보의 전체 val 개선은 균형 정확도 +1.12%p이지만 그룹 분리 시 DINOv2 대비 개선이 유지되지 않았습니다. 전체 정확도는 개선됐습니다. 따라서 균형 정확도의 개선이 확인된 최종안으로 확정하지 않고 후보로 남깁니다. 전체 val에서 기준을 고정한 신발 그룹 부트스트랩 차이 구간도 -0.99 ~ +3.12%p로 0을 포함했습니다.

두 단일 모델이 함께 틀린 148장 중 정상은 123장입니다. 공통 정상 오판의 원인을 점검하는 것이 우선입니다. 현재 하나의 기준 모델을 둔다면 DINOv2를 유지하고 DINOv3를 개선 후보로 검토하는 것을 추천합니다 (사용자 확정 전).

**추가 실험 추천 (확정 전):**

1. GPU를 쓰지 않는 동안에는 출력별 sigmoid 보정 후 평균을 신발 그룹 내부 검증으로 확인합니다. 보정이 단일 모델의 기준 선택 성능을 반드시 높이는 것은 아니며, 앙상블의 점수 눈금을 맞추는 후보입니다. [공식 보정 지침](https://scikit-learn.org/stable/modules/calibration.html)
2. 향후 GPU 사용이 가능해지면 **DINOv3 백본 고정 + 분류층만 학습**을 우선 후보로 둡니다. 한 번 특징을 추출해 저장하면 CLS+평균과 CLS+평균+최댓값 분류층을 CPU에서 비교할 수 있습니다. 초기 특징 추출은 별도 연산이 필요하며 지금은 실행하지 않습니다. [공식 고정 특징 사용법](https://huggingface.co/facebook/dinov3-vitb16-pretrain-lvd1689m)
3. 그다음 후보는 DINOv3 LoRA 학습률을 `1e-4 → 3e-5`로 낮추고 나머지 설정·15 epoch를 유지하는 실험입니다. 사전학습 특징을 덜 바꾸면 도움이 될지 보는 가설이며 최적값이나 개선이 확인된 것은 아닙니다.
4. YOLO·DETR의 같은 val 예측을 받으면 분류기와 탐지기의 조합도 우선 비교합니다. DINOv2의 조건 맞추기용 15 epoch 재학습과 모델 대형화·epoch 증가를 먼저 진행하지 않습니다.

**상세 산출물:** `runs/dino/EX-02_20261018_1024_e15/candidate_avg50_report.md`에 두 평가 방식의 지표 요약 표와 모든 4×4 혼동 행렬을 보존했습니다. 수치·선택 기준·입력 해시는 `candidate_avg50.json`, 내부 검증의 fold별 기준은 `candidate_avg50_groupcv.json`에 있습니다. 평균 후보의 전체 val 기준은 안감 0.73 / 밑창 0.40입니다. 어느 설정도 자동 적용하지 않았습니다.

### 특징 캐시와 장치 사용

최신 사용자 결정에 따라 **GPU 특징 추출 → GPU 분류층 학습 → GPU 최종 val 추론**을 순서대로 실행합니다. 각 단계는 별도 프로세스이며 특징 추출 프로세스가 종료된 뒤 분류층 학습을 시작합니다. 지표 집계·판정 기준 선택은 저장한 확률을 CPU에서 계산합니다.

1. 백본을 `eval()`로 고정하고 모든 파라미터의 gradient를 끕니다. 추출은 `inference_mode`·bf16/SDPA를 사용합니다. 추출 배치는 1부터 짧게 확인하고 기존 reserved 6.5GiB 한도를 지킵니다. 실제 시간·메모리는 아직 측정하지 않았습니다.
2. train 사진마다 좌우 반전 확률 0.5와 밝기·대비·채도 0.9~1.1배의 **약한 증강 4개 view**를 미리 만듭니다. seed·파일명·view 번호로 난수를 고정하고, crop·손상 부위 잘라내기는 사용하지 않습니다. 이미지를 복제해 저장하지 않고 2304차원 특징만 저장합니다.
3. 각 epoch에는 사진당 view 하나만 사용합니다. 이미지별 시작 view를 seed 0으로 고정하고 epoch마다 4개 view를 순환합니다. **epoch당 사진 수는 4,584장**이며 4배로 늘리지 않습니다. 15 epoch 동안 각 view를 3~4회 사용합니다.
4. val은 증강 없이 사진당 특징 하나만 저장합니다. 두 원본 val 분할의 구분은 재현용으로 유지하고, 평가 결과는 1,319장 합산으로만 보고합니다.
5. 캐시는 train `[4584,4,2304]`, val 합계 `[1319,2304]`의 float32 `.npy`를 제안합니다. 총 **19,655개 특징**, 특징 배열만 약 **173MiB**의 용량 추정입니다. 실제 파일 크기·소요 시간 측정값은 아닙니다.
6. 파일명·정답·신발 그룹·view seed·순서와 원본 이미지 해시를 별도 명세에 둡니다. 백본 revision·원본 가중치 해시·LoRA 없음·입력·정규화·pooling·추출 dtype·증강 정책이 다르면 캐시를 재사용하지 않습니다. 접수증 내용이나 사진은 캐시에 넣지 않습니다.
7. 추출 프로세스가 종료된 뒤, 새 GPU 프로세스에서 캐시를 읽어 분류층을 학습합니다. 분류층·특징·정답·손실과 optimizer 갱신 모두 CUDA에서 수행합니다. 백본은 다시 불러오지 않습니다. 최종 val 추론도 별도 GPU 프로세스에서 수행하며 완료 후 GPU를 비웁니다. 실제 분류층 학습 시간은 완료 시 기록합니다.

원본 이미지에 대한 EX-02의 매 epoch 새 증강과 이번의 고정 4-view 캐시는 다릅니다. 백본의 평가 모드와 분류층 float32 연산도 차이가 있습니다. 따라서 결과는 **두 학습 방식의 성능 후보 비교**이며, 차이를 LoRA 유무 하나의 인과 효과로 단정하지 않습니다. 이 제한을 없애기 위한 추가 GPU 대조 실험은 현재 계획에 넣지 않습니다.

### 평가와 선택 기준

- 15 epoch 동안 고정 기준 0.5의 **합산 val** 손실·균형 정확도·전체 정확도를 기록합니다. 선택 가중치는 마지막 epoch이며, 매 epoch 점수를 보고 계획을 바꾸지 않습니다.
- 마지막 분류층을 새 GPU 프로세스에서 재로딩하고, 저장 전후 동일한 val 특징에 대한 logits·확률이 오차 1e-6 이내로 재현되고 혼동행렬이 일치하는지 확인합니다. 선택 기준은 EX-02와 같은 0.01~0.99의 99×99 그리드와 동일한 동점 규칙으로 **한 번** 정합니다. EX-02의 0.93 / 0.23을 그대로 가져오지 않습니다.
- 결과는 **합산 4×4 혼동 행렬 하나 + 지표 요약 표**입니다. 균형 정확도가 핵심이며 전체 정확도·normal/heel/outsole 재현율도 함께 봅니다. both 정답 0장은 N/A로 두고 균형 정확도 평균에서 제외합니다.
- 직접 비교 기준은 EX-02 DINOv3 + LoRA의 균형 정확도 **84.86%**, 전체 정확도 **81.73%**입니다. EX-01 DINOv2도 기존 후보로 유지합니다. 완료한 EX-03은 균형 정확도 **74.23%**, 전체 정확도 **74.98%**로 이번 설정에서는 기존 후보보다 낮았습니다. 특징 추출은 **24분 7초**, GPU 분류층 15 epoch는 **14.14초**가 걸렸습니다.
- 정상 재현율 개선이 heel·outsole 재현율 하락과 함께 나타나는지 확인합니다. 차이가 작으면 한 번의 seed와 val 선택 결과만으로 우열을 확정하지 않습니다. 필요할 때 이미 정한 신발 그룹별 내부 검증 절차를 CPU로 적용하며 최종 test와 구분합니다.
- test는 모델·조합·판정 기준이 어느 정도 확정된 뒤 사용자 요청으로 사용합니다. 이 설계에는 test·새 앙상블·다음 학습의 자동 실행을 포함하지 않습니다.

| 위치 표현 | 학습한 위치 임베딩 보간 | RoPE | v3에는 학습 모드의 위치 좌표 증강도 있음 |
| 연구에서 강조한 점 | 범용 전역·지역 시각 특징 | 규모 확대, 지역 특징 유지, 해상도 유연성 | v3의 지역 특징을 잘 활용하는 분류층은 검토 가치가 있음 |

기초 근거: [DINOv2, Oquab 외, 2023/2024](https://arxiv.org/abs/2304.07193), [DINOv3, Siméoni 외, 2025](https://arxiv.org/abs/2508.10104). DINOv3의 Gram anchoring은 사전학습 과정의 지역 특징 품질을 다룬 기법입니다. 사전학습을 재현하거나 우리 LoRA 손실에 그대로 추가할 계획은 아닙니다.

2026년의 산업 검사 연구는 RGB와 X-ray, 백본 고정과 전체 미세조정에서 결과가 달랐습니다. ConvNeXt 기반 비교이므로 우리 ViT-B 두 모델의 순위를 직접 증명하지 않습니다. **도메인·적응 방식에 맞춰 검증해야 한다는 근거**로 사용합니다. [Gharbage 외, CVPR VISION 워크숍 2026](https://arxiv.org/abs/2605.23472)

**A1/A2의 해석:** 적은 비용으로 고정 특징 분류기의 설정을 다시 확인할 수 있습니다. 결과가 좋아도 LoRA의 pooling 변경 효과를 입증한 것은 아닙니다. 정규화 통계는 train만 사용하고 val로 맞추지 않습니다. 같은 분류층의 수렴이 부족한지 먼저 학습 곡선을 확인하고, 필요하면 train 내부 검증으로 정규화된 로지스틱 분류기를 별도 후보로 정합니다. 여러 정규화·분류기 설정을 전체 val에 무제한 탐색하지 않습니다. CLS+평균 분류 사용법의 근거는 [Meta 공식 모델 카드](https://huggingface.co/facebook/dinov3-vitb16-pretrain-lvd1689m)입니다.

**특징 결합과 지역 정보:** register 연구는 배경의 일부 고노름 토큰이 지역 특징에 영향을 줄 수 있음을 보였습니다. 이것이 현재 오판 원인이라고 확인한 것은 아닙니다. 단순 최댓값 제거는 우리 코드에 대한 가설이며, v3에서 register를 이미 제외한 점도 구분합니다. [Vision Transformers Need Registers, ICLR 2024](https://arxiv.org/abs/2309.16588)

**B3에서 새로 확인한 코드 사실:** 현재 v3 snapshot의 `pos_embed_rescale=2.0`과 설치된 Transformers 코드를 확인했습니다. `model.train()` 때 패치 위치 좌표의 범위를 0.5~2배로 무작위 조절합니다. 이미지 픽셀을 흐리는 증강은 아닙니다. 이미지 단계에는 앞서 설명한 반전·밝기·대비·채도 네 종류를 쓰고, 모델 내부에는 이 위치 증강이 추가로 있습니다. 고정 특징 EX-03은 `eval()`이어서 적용되지 않았습니다. 좌표 증강의 연구 근거는 DINOv3 §3.2, 구현 근거는 [Transformers 공식 소스](https://github.com/huggingface/transformers/blob/main/src/transformers/models/dinov3_vit/modeling_dinov3_vit.py)입니다. `backbone.eval()`로 LoRA dropout까지 함께 끄는 방식 대신 해당 설정만 별도로 비교해야 합니다.

**C1/C2의 논문 근거:** [LoRA+, ICML 2024](https://proceedings.mlr.press/v235/hayou24a.html)는 A/B 행렬에 다른 학습률을 적용합니다. [DoRA, ICML 2024](https://proceedings.mlr.press/v235/liu24bn.html)는 가중치 크기와 방향을 나누어 적응합니다. 주된 검증 과제가 우리 DINO 신발 분류와 같지 않으므로 개선율을 가져오지 않습니다. [Learning Rate Scaling across LoRA Ranks and Transfer to Full Finetuning, 2026](https://arxiv.org/abs/2602.06204)는 rank·초기화·스케일·학습률의 상호작용을 분석합니다. r을 키울 때 alpha/r와 학습률도 확인해야 하며 rank만 키우면 좋아진다는 근거가 아닙니다. 구현 후보는 [PEFT 공식 문서](https://huggingface.co/docs/peft/package_reference/lora)를 따르고 현재 설치본 호환성은 실행 전 점검합니다.

**C3의 범위:** [AugMix, ICLR 2020](https://arxiv.org/abs/1912.02781)은 증강과 일관성 학습을 통한 강건성 근거입니다. 단순 blur 추가를 AugMix 재현이라고 부르지 않습니다. blur는 작은 손상 단서를 지울 수 있으므로 실제 열화가 있을 때 약하게 비교합니다. [CutMix, ICCV 2019](https://arxiv.org/abs/1905.04899)는 영역 혼합과 면적 기반 라벨 혼합을 사용합니다. 손상이 작은 부분에 몰린 우리 사진에서는 면적 비율과 손상 존재 여부가 다를 수 있습니다. 모자이크·무작위 crop·강한 blur·CutMix는 우선 후보에서 내립니다. 손상 박스를 고려한 별도 라벨 정책이 필요합니다.

**손실 함수:** [Asymmetric Loss, ICCV 2021](https://openaccess.thecvf.com/content/ICCV2021/html/Ridnik_Asymmetric_Loss_for_Multi-Label_Classification_ICCV_2021_paper.html)는 다중 라벨의 쉬운 음성을 약하게 반영하는 기법입니다. 우리는 두 출력뿐이고 정상 오판이 핵심이어서 기본 ASL/Focal 설정이 맞는다고 보기 어렵습니다. 현재 BCE의 pos_weight, 클래스별 정밀도·재현율과 점수 순위를 먼저 확인합니다. 기준값이 극단적이라는 이유만으로 손실을 바꾸지 않습니다.

지역 패치 attention이나 박스 보조 손실은 train의 라벨만 씁니다. 박스 밖 전체를 무조건 정상 패치로 단정하지 않습니다. 현재 173MiB 캐시는 CLS·평균·최댓값만 저장해 위치 정보가 없으므로 attention pooling·이상 지도 학습에는 재사용할 수 없습니다. 새 특징 처리·학습이 필요합니다.

### YOLO·DETR과 결합하는 기본안

**우선 비교할 구조는 사진 전체 분류와 손상 탐지를 각각 수행한 뒤 사진별 점수를 합치는 방식입니다.** 탐지기의 손상 위치 근거가 DINO의 전역 특징과 보완적인지 검증합니다. 아직 팀원 예측을 받지 않았으므로 어느 조합이 우세한지는 미확인입니다.

1. DINO는 사진별 `p_heel_lining, p_outsole` 두 점수를 냅니다.
2. 탐지기는 각 클래스의 박스 점수 중 최댓값을 사진 점수로 변환합니다. 같은 클래스의 박스가 없으면 0입니다. 미처리·누락 사진과 빈 탐지는 구분합니다.
3. 필요하면 점수 눈금을 보정하고, 두 클래스에 각각 모델 점수를 평균합니다. 두 점수를 softmax로 묶지 않습니다.
4. 합산 val에서 고른 heel·outsole 기준을 적용해 normal / heel / outsole / both를 냅니다. both 정답이 없는 val에 맞춰 both 출력을 금지하지 않습니다.

탐지 점수는 보정 전에는 잘 보정된 사진 단위 확률이라고 가정하지 않습니다. 여러 박스의 `1-∏(1-score)` 합성은 중복·상관된 박스가 점수를 부풀릴 수 있어 초기 후보는 최댓값으로 고정합니다.

가장 먼저 고정할 소수의 결합 후보는 다음과 같습니다. 각 모델 단독 결과도 함께 보존합니다.

| 결합 후보 | 클래스별 사진 점수 |
|---|---|
| DINOv3 + YOLO | `0.5×D3 + 0.5×Y` |
| DINOv3 + DETR | `0.5×D3 + 0.5×R` |
| DINOv3 + YOLO + DETR | `0.5×D3 + 0.25×Y + 0.25×R` |

여기서 R은 먼저 정한 탐지기 하나입니다. RF-DETR·RT-DETR을 조합마다 임의로 교체하며 전체 val 점수를 최대화하지 않습니다. 탐지기 후보 선택부터 내부 검증에 포함합니다. DINOv2의 예측도 같은 결합에 대입해 비교할 수 있지만, 우선 후보군을 정한 뒤 한꺼번에 평가합니다. 세 모델 평균에서 분류기·탐지기 계열에 각각 절반을 주는 것은 프로젝트의 출발 가설이며 최적 가중치라는 뜻이 아닙니다.

**RF-DETR의 실제 백본도 확인해야 합니다.** 공식 문서의 Nano~Large 모델은 DINOv2 계열을 사용합니다. 따라서 DINO 분류기와 완전히 독립된 특징이라고 가정하지 않습니다. 탐지 과제·구조가 달라 보완 가능성은 남고, 실제 공동 오판으로 판단합니다. 다른 변형은 체크포인트별로 확인합니다. [RF-DETR 공식 문서](https://rfdetr.roboflow.com/latest/learn/run/detection/), [RF-DETR 논문, 2025/2026](https://arxiv.org/abs/2511.09554). RT-DETR의 연구 근거는 [DETRs Beat YOLOs, CVPR 2024](https://openaccess.thecvf.com/content/CVPR2024/html/Zhao_DETRs_Beat_YOLOs_on_Real-time_Object_Detection_CVPR_2024_paper.html)이며 COCO AP가 우리 사진 판정 점수를 대신하지 않습니다.

### 점수 보정·학습형 결합·검증

[Guo 외, ICML 2017](https://proceedings.mlr.press/v70/guo17a.html)는 온도 보정을 연구했습니다. 우리 시스템은 두 독립 sigmoid 출력이므로 다중 클래스 softmax 보정을 그대로 적용하지 않습니다. 탐지기의 사진 점수에도 클래스별 sigmoid 보정을 별도로 검토하고, 확률 보정과 분류 기준 선택은 구분합니다. 단조 보정은 단일 모델의 순위나 최적 기준 성능을 반드시 개선하지 않지만 서로 다른 모델의 평균에는 영향을 줄 수 있습니다. [scikit-learn 공식 보정 설명](https://scikit-learn.org/stable/modules/calibration.html)

추천 순서는 고정 평균 → 보정 후 고정 평균 → 제한된 가중 평균 → 정규화한 로지스틱 결합입니다. 마지막 방법은 모델의 예측 점수로 최종 판단을 학습하는 stacking입니다. 처음에는 클래스별 같은 클래스 점수 3개만 사용해 두 개의 이진 결합기를 만들고, 복잡한 MLP나 많은 박스 특징은 넣지 않습니다. [Wolpert, Stacked generalization, 1992](https://doi.org/10.1016/S0893-6080(05)80023-1), [공식 StackingClassifier 문서](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.StackingClassifier.html)

- 원본 train·val·test 분할은 유지합니다. val 내부에서만 기존 신발 그룹을 묶은 5-fold를 사용합니다. 보정·가중치·판정 기준은 해당 fold의 평가 사진을 제외하고 학습합니다. 추가 설정을 고를 경우 그 선택도 학습 쪽 내부 분할에서 수행합니다.
- 기존 모델 개발에 전체 val을 사용했으므로 이 절차도 독립적인 최종 일반화 평가나 백본 전체의 교차검증은 아닙니다. 목적은 같은 점수로 보정·조합을 맞추고 같은 사진에서 점수를 재는 낙관을 줄이는 것입니다.
- 마지막에는 설정을 고정하고 전체 val로 보정·판정 기준을 다시 맞춥니다. test는 사용자와 모델·조합을 확정한 뒤 사용합니다.
- 보고는 합산 4×4 혼동 행렬과 지표 요약 표입니다. 핵심은 균형 정확도이며 전체 정확도·정상 오판·heel/outsole 재현율도 확인합니다. 모델 간 짝지은 신발 그룹 부트스트랩과 조합 전후의 공동 오판도 보조로 봅니다.
- 모델별 단독 점수보다 결합 후 개선을 기준으로 선택합니다. 차이가 불확실하면 모델 수가 적고 재현 가능한 후보를 우선합니다.

### 결합에서 후순위로 둘 방식

- **박스 WBF:** [Weighted Boxes Fusion, 2021](https://arxiv.org/abs/1910.13302)는 탐지 박스의 결합 기법입니다. 박스 위치가 채점 대상이 아닌 현재 과제에서는 사진 점수 결합을 먼저 검증합니다. WBF의 박스 AP 개선이 사진 판정 개선을 보장하지 않습니다.
- **강제 AND/OR:** 탐지기와 분류기가 모두 동의해야 손상으로 보거나, 하나라도 손상이면 손상으로 보는 규칙은 각각 손상 누락·정상 오판의 교환을 일으킵니다. 부드러운 점수 결합을 우선합니다.
- **탐지→crop→DINO 연쇄:** 작은 손상의 확대 가능성은 있지만 탐지 실패를 물려받고, 전체 사진용 분류기가 crop에도 맞는지 별도 검증이 필요합니다. 검토하더라도 전체 사진 분류 경로를 유지하는 추가 분기로 시작합니다. 현재 기본 설계는 병렬 점수 결합입니다.
- **대형 모델·전체 fine-tuning:** B 모델·분류층·결합을 먼저 검토합니다. 마지막 일부 블록 미세조정이나 ViT-L은 이후 후보이며 RTX 5060 8GB에서 메모리·시간을 짧게 확인해야 합니다. 새 모델이 현재 데이터에서 더 좋다는 측정은 없습니다.

## EX-04 학습된 DINOv2 LoRA 고정 후 분류층 정규화

**상태:** 정규화 비교·합산 val 평가 완료

**사용자 결정:** 2026-10-18, DINOv2 + LoRA와 DINOv3 + LoRA 두 모델에 특징 정규화 실험을 적용하고 결과를 비교합니다. 이 요청은 두 실험의 순차 실행과 합산 val 평가를 포함합니다. test와 다른 후속 학습은 포함하지 않습니다.

**원본:** EX-01의 `last_epoch12.pt`. 원래 30 epoch 스케줄을 12 epoch에서 중단한 학습된 LoRA·백본·분류층을 읽습니다. 원본 가중치·판정 기준·결과는 보존합니다.

**방법:** 학습된 LoRA와 백본은 고정하고 `eval()`로 특징을 추출합니다. train은 약한 증강 4개 고정 view, val은 무증강입니다. train 추출 batch 4, 기존 val 재현 추출 batch 1, 입력 1022입니다. 특징은 CLS+패치 평균+최댓값의 2304차원이며 새 전용 캐시를 사용합니다. EX-03 원본 백본 캐시는 사용하지 않습니다.

**정규화:** 각 특징 차원의 평균·모표준편차를 train 4-view에서만 계산합니다. 표준편차 하한은 1e-6입니다. 정규화 없는 분류층과 정규화한 분류층을 같은 캐시·view 순환·셔플·학습률로 15 epoch 비교합니다. 둘 다 원래 분류층에서 출발하며, 정규화한 분류층은 `W'=W×std`, `b'=b+W×mean`으로 변환해 초기 판정 함수를 유지합니다. 선형 분류기의 표현력 증가가 아닌 최적화·weight decay 작용의 차이를 봅니다.

**학습·평가:** 분류층 4,610개만 GPU float32, TF32 비활성화, batch 8, AdamW LR 1e-3, weight decay 0.01, clip 1, warmup 1 epoch와 15 epoch cosine. 마지막 epoch를 사용합니다. 기준은 각 조건의 합산 val에서 기존 99×99 그리드로 한 번 선택합니다. 별도 GPU 프로세스 재로딩 검증, 원본 val 확률·혼동행렬 재현, 캐시·데이터·원본 checkpoint·새 소스 해시를 확인합니다. 비교 보고서는 원본/정규화 없는 대조군/정규화 적용을 구분합니다.

**해석:** 원본 대비 변화에는 분류층 추가 학습·고정 4-view·백본 eval·FP32 분류층 차이가 포함됩니다. 정규화의 직접 비교는 같은 조건의 대조군과 정규화 분류층입니다. 모델·조합을 최종 확정하기 전 test는 사용하지 않습니다. 실행 경로는 `normalized_probe/`입니다.

LoRA+는 학습률 비율만 달리합니다. 분류층 LR·적용 모듈·weight decay·모델 구조·데이터·seed는 유지합니다. 비율 16은 [PEFT 공식 예시](https://huggingface.co/docs/peft/package_reference/lora#lora-optimized-lora)의 출발값이며 우리 데이터에서 최적이라고 확인한 값은 아닙니다. 방법의 근거는 [LoRA+, ICML 2024](https://proceedings.mlr.press/v235/hayou24a.html)입니다. 15 epoch 소요 시간은 기존 EX-06의 실행 속도를 바탕으로 약 5시간을 예상하며 실측은 완료 후 기록합니다.

`classifier/dino/lora_plus_tta/`를 별도 경로로 추가했습니다. 진행 중인 EX-06이 검증할 `model.py`·`train.py`·`tools/*.py`는 변경하지 않습니다. 원본 protocol·config·체크포인트·확률·지표는 덮어쓰지 않습니다. 후속 코드와 공유 소스, 공식 optimizer 소스·백본 해시를 봉인하고 `source_snapshot/`에 보존합니다. EX-07은 실행 직전 train 128장 GPU 점검을 통과해야 본 학습을 새로 시작합니다. 설정은 EX-07 run의 `config.json`, 추가 실행의 출처는 `extension_protocol.json`과 후속 경로의 `protocol.json`을 따릅니다.

### TTA와 비교 방법

두 모델 모두 **원본 + 좌우 반전**의 2-view를 사용합니다. EXIF 방향을 처리한 사진을 좌우 반전한 뒤 기존 resize·패딩·ImageNet 정규화를 적용합니다. 이미지 단계의 색 증강·crop은 TTA에 추가하지 않습니다. 각 view의 heel·outsole sigmoid 점수를 각각 50:50 평균합니다. softmax나 4클래스 점수 평균으로 바꾸지 않습니다.

같은 최종 가중치의 원본 val 예측을 다시 추론해 기존 CSV와 확률 오차 `1e-4` 이내·혼동행렬 일치를 확인합니다. TTA의 원본·반전·평균 확률은 별도로 저장합니다. 각 방식의 판정 기준은 같은 합산 val에서 기존과 같은 0.01~0.99 격자로 각각 선택합니다. 원본 판정 기준을 그대로 썼을 때의 TTA 지표도 별도 저장해 점수 평균과 기준 재선택을 구분할 수 있게 합니다. 합산 val 1,319장의 4×4 혼동행렬과 지표 요약 표로 비교합니다. 이 결과는 같은 val을 반복 사용한 개발 결과이며 test는 보류합니다. [TTA 연구, ICCV 2021](https://arxiv.org/abs/2011.11156)

선행 EX-06 wrapper의 프로세스 종료·`[exit 0]`·최종 val·예측 검증 성공을 모두 확인한 뒤 후속 GPU 작업을 시작합니다. 원본 TTA가 끝나면 **전후 비교 표와 혼동행렬을 콘솔·Markdown에 출력한 뒤에만** LoRA+ 점검·학습을 시작합니다. 마지막에도 **LoRA / LoRA + TTA / LoRA+ / LoRA+ + TTA** 네 결과를 콘솔·JSON·Markdown·이 문서에 출력합니다. GPU 단계는 자식 프로세스를 하나씩 실행하고, 각 종료를 기다립니다. 한 단계라도 실패하면 다음 학습을 시작하지 않습니다.

**2026-10-19 후속 대화 반영:** 처음 제안한 `mosaic=0.5`·`scale=0.3` 대신 `mosaic=0.2`·`scale=0.2`로 설계합니다. 사용자는 작은 뒷축 손상의 축소·잘림을 우려했고, 낮은 적용 빈도의 절충안을 논의한 뒤 설계를 요청했습니다. 이후 9번까지의 진행을 승인했습니다. 구체적인 순서와 평가 방법은 아래 **YOLO-01 실험 설계**를 따릅니다.

| 항목 | 추천 출발 설정 | 목적 |
|---|---|---|
| 모델·입력 | `yolo26m.pt`의 COCO 가중치, 1024 입력 | 기존 큰 입력 사본과 미세 손상 활용 |
| 학습 범위 | 백본·neck·두 헤드 전체, `freeze=None` | 신발 손상 도메인에 적응 |
| 데이터 | v5 train 4,584장 모두, 기존 split 유지 | 정상·다른 각도 정상도 음성으로 학습 |

| 색·반전 | `fliplr=0.5`, `hsv_h=0.01`, `hsv_s=0.3`, `hsv_v=0.2` | 방향·조명 변동에 적응 |

증강·warmup·cosine·EMA는 한 묶음으로 적용 가능한 출발 구성입니다. 이 묶음과 비교할 YOLO 기준 실험은 아직 없으므로 각각의 기여나 개선율을 주장하지 않습니다. `nbs`에 따른 누적은 optimizer 갱신을 위한 것이며 BatchNorm의 물리 배치 통계를 크게 만들어 주지는 않습니다. 시간·최대 메모리는 mosaic와 optimizer state가 생긴 실제 짧은 학습으로 확인하고 정합니다.

**증강 관련 주의:** DINO는 사진 라벨을 유지하며 crop하면 손상이 사라질 수 있었지만, YOLO는 변환한 박스와 잘린 박스를 함께 처리합니다. 따라서 Mosaic을 일괄 배제하지 않습니다. 반대로 박스가 있어도 너무 작은 손상·불완전한 박스가 과한 변형에서 사라질 수 있으므로 실제 학습 배치를 확인합니다. 현재 YOLO 환경에는 Albumentations 배포 패키지가 없습니다. 향후 설치하면 기본 Blur·MedianBlur·ToGray·CLAHE가 각 p=0.01로 추가될 수 있으므로 실제 pipeline을 기록해야 합니다. `erasing=0`을 넣었다고 탐지 blur를 끈 것으로 해석하지 않습니다.

### 같은 가중치로 먼저 비교할 추론 후보

1. **NMS 사용 헤드와 NMS 없는 헤드:** 학습을 두 번 하지 않고 같은 50 epoch 가중치의 각 헤드로 합산 val을 평가합니다. 공개 모델의 COCO AP 차이를 참고하되 사진 단위 균형 정확도로 선택합니다. 두 헤드를 독립된 새 학습 모델로 세지 않습니다.
2. **선택한 헤드의 원본+좌우 반전 TTA:** 두 view에서 클래스별 최대 박스 점수를 얻어 50:50 평균합니다. 원본 bbox는 따로 보존하고 시각화 때 반전 좌표를 되돌립니다. 사진 판정용 두 점수 평균에는 박스 매칭이 필수는 아닙니다. TTA의 판정 기준도 다시 val에서 선택합니다.
3. **필요 시 작은 손상용 SAHI:** 전체 사진 추론을 유지한 추가 타일 분기를 검토합니다. 이미 1024로 축소한 사진을 확대해도 잃은 원본 디테일은 복원되지 않습니다. 원본/큰 사본의 확보, 입력 배율 변화와 정상 오탐을 같이 확인해야 합니다. 타일 수를 늘리면 클래스별 max가 높아질 수 있으므로 기준도 별도로 검증합니다.

**TTA 구현 확인:** 설치된 `nn/tasks.py`의 `DetectionModel._predict_augment()`는 end-to-end 헤드에서 `augment=True`를 단일 추론으로 되돌립니다. 명시적인 원본·반전 두 번의 추론과 view별 저장·재현 검증을 권장합니다. 이 버전의 predictor/validator는 `nms=None`과 `nms=False`로 두 헤드를 선택하므로 최신 문서의 API 예제를 그대로 넘기지 않고 설치본에서 실제 head를 확인해야 합니다. [공식 소스 API](https://docs.ultralytics.com/reference/nn/tasks/#ultralytics.nn.tasks.DetectionModel._predict_augment), [공식 dual-head 설명](https://docs.ultralytics.com/models/yolo26/#usage-examples)

### YOLO 단독과 DINO·RF/RT-DETR 앙상블

기본 결합은 사진 전체에 각 모델을 병렬로 적용하고 사진별 두 점수를 합치는 방식입니다. 탐지기가 놓친 위치는 crop 경로에도 들어가지 못하므로, YOLO가 찾은 crop만 DINO에 넘기는 연쇄 방식은 별도의 후순위 실험입니다. 작은 손상 crop 분류를 검토할 때에도 전체 사진 분류 경로와 ROI 전용 학습·맥락 문제를 함께 봅니다.

먼저 비교할 후보를 미리 제한합니다. 각 모델의 단독 결과도 모두 유지합니다.

| 후보 | 클래스별 출발 결합 |
|---|---|
| YOLO 단독 | YOLO의 해당 클래스 최대 박스 점수 |
| DINO 단독 | 기존 DINO 후보의 sigmoid 점수 |
| DINO + YOLO | `0.5 D + 0.5 Y` |
| YOLO + RF-DETR | `0.5 Y + 0.5 RF` |
| YOLO + RT-DETR | `0.5 Y + 0.5 RT` |
| DINO + YOLO + 선택한 DETR 하나 | 출발안 `0.5 D + 0.25 Y + 0.25 R` |

가중치는 최적값으로 주장하지 않습니다. 단독 또는 두 모델과 비교해 실제 추가 이득이 있을 때 모델을 더 포함합니다. RF와 RT 중 하나를 선택하는 절차도 검증 안에 넣습니다. 세 모델 이상이 항상 더 좋다는 보장은 없습니다. 차이가 불확실하면 단순한 후보를 우선합니다.

**결합 방법의 순서:** 고정 평균 → 클래스별 보정 후 평균 → 소수의 가중 평균 → L2 로지스틱 결합(두 이진 출력). 모델별 own-class 점수부터 사용해 복잡한 MLP나 다수 박스 통계로 바로 늘리지 않습니다. [보정 연구](https://proceedings.mlr.press/v70/guo17a.html), [Stacking 공식 문서](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.StackingClassifier.html)

**RF-DETR의 보완성:** 보통 Nano~Large RF-DETR은 DINOv2 백본을 사용하므로 DINO 분류기와 완전히 독립적이라고 가정하지 않습니다. 다른 변형의 백본은 실제 모델 이름으로 확인합니다. CNN 계열 YOLO와 ViT 계열 DINO가 다른 오류를 만들 가능성은 있지만, 이를 결합 효과로 확정하는 근거는 실제 같은 사진의 공동 오판과 검증 결과입니다. [RF-DETR 공식 문서](https://rfdetr.roboflow.com/latest/learn/run/detection/)

우리 목표는 사진 판정이므로 WBF·Soft-NMS·box IoU 최적화는 사진 점수 결합보다 후순위입니다. 단순 AND는 탐지 누락을, OR/noisy-OR는 정상 오탐을 늘릴 수 있습니다. 두 손상 출력을 softmax로 묶거나 both가 없는 val에 맞춰 both 출력을 금지하지 않습니다.

### 평가·재현·팀원 산출물

- 학습은 기존 v5 train만 사용합니다. 논문 분할로 학습한 YOLO·DETR 가중치는 현재 val/test와 겹칠 수 있어 사용하지 않습니다. COCO 사전학습 가중치에서 새로 시작합니다.
- 합산 val **639+680=1,319장**의 사진 단위 균형 정확도·전체 정확도·클래스별 재현율, 4×4 혼동행렬로 비교합니다. val25의 txt는 손상 사진도 비어 있으므로 이를 정상 박스 GT로 간주해 합산 mAP를 내지 않습니다. 박스 mAP는 GT가 있는 v5 val의 보조 지표입니다.
- 탐지 예측은 표시용 기준 0.25/0.5로 먼저 자르지 않고 `conf=0.001` 수준까지 저장합니다. 사진별 점수는 해당 클래스 박스 점수의 max이고 빈 탐지는0, 실패·미처리는 별도 상태입니다. 원본 박스·class map·threshold·NMS/헤드·max_det·TTA·해상도·전처리를 보존합니다.
- 보정·가중치·threshold는 신발 group을 나눈 val 내부5-fold에서 해당 평가 fold를 제외하고 맞춥니다. 후보 선택이 추가되면 그 선택도 학습 쪽 내부 분할에서 합니다. 이미 전체 val로 모델을 개발했으므로 이 결과 역시 독립적인 test 평가나 백본 전체의 교차검증은 아닙니다.
- 모델 설정을 정한 뒤 전체 val로 판정 기준을 맞추고, 최종 모델·조합 확정 후 test를 사용합니다. 단독과 결합의 차이는 같은 신발 그룹의 짝지은 부트스트랩을 보조로 봅니다. 아주 작은 val 차이를 확정적 우위라고 하지 않습니다.
- 팀원에게 받을 최소 형식은 `file,p_heel_lining,p_outsole`과 처리 상태입니다. 실제 가중치·학습 데이터/분할·run 설정·패키지·원본 박스·전처리·last/EMA/best 구분도 받습니다. 아직 팀원에게 메시지를 보내거나 형식을 확정하지 않았습니다.

**추천 진행:** 첫 YOLO26m·1024 학습에 위의 증강·스케줄·EMA 묶음을 적용 → 같은 last EMA의 두 헤드·명시적 좌우 반전 TTA 평가 → YOLO 단독과 DINO+YOLO 비교 → 팀원 RF/RT 예측 도착 후 소수 결합 비교입니다. YOLO 단독이 최종 기준에서 충분하거나 결합 이득이 없으면 DINO를 포함하지 않는 후보도 그대로 선택할 수 있습니다. 새로운 본 학습은 이 조사와 별도로 사용자가 진행을 요청한 뒤 시작합니다.

### 목표와 현재 실험의 종료 조건

- 목표는 손상 위치 자체보다 사진별 `normal / heel / outsole / both`의 최종 판정을 잘하는 것입니다. YOLO 단독으로 충분하면 단독 모델도 선택합니다.
- 진행 중인 순서 `EX-06 최종 val → LoRA TTA·전후 보고 → EX-07 LoRA+ 15 epoch·최종 val → LoRA+ TTA·네 결과 보고`를 그대로 마칩니다. YOLO 준비 때문에 이 순서나 실행 소스를 바꾸지 않습니다.
- 후속 실행기는 위 순서의 성공·최종 보고서·wrapper 종료 코드0·GPU 프로세스 종료를 확인합니다. `nvidia-smi`로 사용 중인 다른 작업과 여유 메모리를 다시 확인한 뒤 점검합니다. 실패하거나 학습 프로세스가 남으면 다음 GPU 작업을 시작하지 않습니다.
- 현재 DINO 15 epoch 설정을 YOLO에 그대로 적용하지 않습니다. YOLO의 전체 미세조정·학습률·누적 방식이 다르므로 첫 탐지기 출발안은 50 epoch으로 잡습니다. 최종 성능이 목적이며 같은 epoch 수의 백본 비교 실험은 아닙니다.

`cache=False`여도 Ultralytics는 label cache를 만들 수 있습니다. workspace 데이터 사본의 파생 `.cache`만 허용하며 이미지·txt·CSV·manifest 내용은 보존하고 전후 해시를 확인합니다. 학습 API가 종료 후 `best.pt`를 다시 검증하거나 반환하더라도, 최종 사진 평가기는 **해당 run의 `weights/last.pt`를 명시적으로 다시 로드**합니다. 이것을 마지막 EMA 가중치로 구분해 저장하고 head별 평가가 같은 SHA256인지 확인합니다.

현재 1024 입력에서도 heel_lining 손상 박스의 24.48%는 짧은 변 32px 미만입니다. 이 통계는 Mosaic이 유해하다는 증명이 아니라, 낮은 빈도·작은 배율 변화로 시작하고 샘플을 확인할 이유입니다. 약20%는 기대 빈도이며 실제 한 epoch의 정확한 비율은 달라질 수 있습니다. Mosaic의 합성 경계 잘림은 `scale`을 낮춰도 남습니다. [Mosaic·scale 공식 설명](https://docs.ultralytics.com/guides/yolo-data-augmentation/)

실행 전 CPU에서 train만 사용한 일반 입력과 Mosaic 입력을 비교합니다. 특히 작은 뒷축·밑창 손상이 축소·경계 잘림 뒤에도 보이는지, 박스 좌표가 맞는지 점검합니다. 미리보기를 남기면 ignored run 안에만 저장하고 접수증 개인정보를 문서나 외부 서비스에 옮기지 않습니다. 이 확인 전에는 증강이 손상 단서를 보존한다고 가정하지 않습니다.

### GPU 점검과 승인된 실행 순서

1. **CPU 점검:** train/두 val의 파일·정답·클래스 이름·해시·중복을 검증하고, train 증강 샘플과 출력 경로를 확인합니다. test 사진·정답을 분석하지 않습니다.
2. **짧은 GPU 점검:** train 128장의 고정 표본에 정상·두 손상·both와 작은 손상을 포함합니다. 본 설정의 batch2·AMP·AdamW로 최소 두 번 optimizer 갱신, 검증, 저장·재로딩까지 확인합니다. 실제 Mosaic 사례와 optimizer state가 만들어진 뒤의 최대 allocated/reserved·장치 메모리를 측정합니다. 학습 중 박스 val은 배치가 기본적으로 두 배, worker도 늘어날 수 있어 그 구간도 확인합니다.
3. **메모리 기준:** 기존 작업의 6,656MiB 예산 안에서 다른 앱 사용량과 GPU 총 여유를 함께 확인합니다. 초과·공유 메모리 사용·OOM이면 batch1로 재점검합니다. 1024 해상도나 모델 크기를 자동으로 바꾸지 않습니다. batch1도 실패하면 점검 실패를 보고하고 학습을 시작하지 않습니다.
4. **본 학습:** 점검용 가중치를 버리고 같은 COCO 가중치·seed0에서 50 epoch을 새로 시작합니다. 확정한 실제 batch·누적·패키지·초기 가중치 해시·실행 소스를 기록합니다. 메모리가 예상과 다르거나 loss가 NaN이면 다음 단계로 넘기지 않습니다.
5. **최종 평가:** 본 학습 성공과 프로세스 종료를 확인하고 아래 사진 단위 네 후보를 순차 평가합니다. 학습·다른 평가 프로세스를 동시에 GPU에 올리지 않습니다.
6. **보고:** 합산 val 지표·혼동행렬·DINO 대비·고정 평균 결합을 정리하고 GPU를 비웁니다. 다음 본 학습이나 test는 결과 보고 후 별도 요청을 기다립니다.

128장 점검만으로 긴 학습의 최대 메모리를 보장하지 않습니다. 본 학습의 초기 epoch도 관찰하고, 실제 두세 epoch가 쌓이면 실측 속도로 남은 시간을 갱신합니다. 학습 시간은 아직 측정하지 않았으며 과거 소규모 YOLO나 DINO의 epoch 시간으로 확정하지 않습니다.

### 추가 학습 없이 비교할 네 YOLO 후보

최초 본 학습의 **동일한 마지막 EMA**에서 다음 네 개를 미리 고정합니다. 이는 학습 네 번이 아니라 학습 한 번과 추론 비교 네 개입니다.

| ID | 탐지 헤드 | 입력 view | 사진 점수 |
|---|---|---|---|
| Y1 | one-to-many·NMS 사용 | 원본 | 클래스별 최대 박스 점수 |
| Y2 | one-to-many·NMS 사용 | 원본+좌우 반전 | view별 최대 점수를 클래스별 50:50 평균 |
| Y3 | one-to-one·NMS 없음 | 원본 | 클래스별 최대 박스 점수 |
| Y4 | one-to-one·NMS 없음 | 원본+좌우 반전 | view별 최대 점수를 클래스별 50:50 평균 |

설치본 `engine/predictor.py`는 `nms=None`일 때 외부 NMS, `nms=False`일 때 NMS-free 경로를 선택합니다. 각 head는 **새 predictor 또는 별도 프로세스**에서 로드해 이전 추론기의 head 설정이 남지 않게 합니다. 실제 선택 branch·head 존재를 확인하고 저장합니다. `augment=True`가 반전 추론을 대신했다고 간주하지 않고, 사진을 명시적으로 반전해 두 번 추론합니다. API가 head 선택을 지원하지 않거나 원본 재현 검증에 실패하면 해당 후보를 성공으로 표시하지 않습니다.

사진 점수 수집은 `conf=0.001`, `iou=0.7`, `max_det=300`, class-aware NMS, FP32 추론을 출발값으로 고정합니다. NMS-free 후보는 NMS IoU가 적용되지 않음을 기록합니다. 0.25/0.5 표시용 기준으로 박스를 먼저 버리지 않습니다. 정상적인 무검출은 해당 클래스 점수0이고, 이미지 누락·오류는 0으로 대체하지 않습니다. 잘린 top-k/max_det 도달 여부도 기록합니다.

원본·반전 raw box와 클래스별 점수는 각각 보존합니다. 사진 판정에는 박스 매칭이나 WBF가 필요하지 않습니다. 반전 박스를 그림에 표시할 때만 좌표를 되돌립니다. 동일 head의 원본을 다시 추론해 CSV 점수 차이 `1e-4` 이내·혼동행렬 일치를 확인하고, TTA 평균이 저장한 두 view의 산술평균인지 확인합니다.

### 공통 평가와 출력

탐지 점수를 `p_heel_lining`, `p_outsole` 열로 이름에 따라 매핑합니다. 독립된 두 점수를 각각 판정 기준과 비교해 둘 다 미만이면 normal, heel만 이상이면 heel, outsole만 이상이면 outsole, 둘 다 이상이면 both로 정합니다. 두 손상 점수를 softmax로 만들거나 both 출력을 금지하지 않습니다. 탐지 점수는 보정된 확률이라고 가정하지 않습니다.

각 후보의 판정 기준 두 개는 기존 DINO와 같은 합산 val에서 같은 `0.01~0.99` 격자로 고릅니다. 균형 정확도 우선, 동률 처리도 기존 평가 함수와 동일하게 고정합니다. 사진별 예측을 합친 뒤 혼동행렬을 만들며 시기별 지표 두 개의 단순 평균은 사용하지 않습니다.

- 핵심 지표: normal·heel·outsole 재현율의 평균인 **균형 정확도**.
- 함께 보고할 값: 전체 정확도, 클래스별 재현율, normal 오탐률(1−normal 재현율), 두 판정 기준, 추론 시간·GPU 메모리.
- 출력: 후보별 **합산 val 1,319장의 4×4 혼동행렬 + 지표 요약 표**. 행·열은 `normal, heel, outsole, both` 순서입니다. both 정답0은 재현율 N/A로 두고 균형 정확도 평균에서 제외하되 both 오예측은 오답입니다.
- 보조 지표: bbox GT가 있는 v5 val 639장의 mAP50·mAP50-95. 이 지표를 합산 사진 판정 지표 대신 사용하거나 val25의 빈 박스를 정상 GT로 합치지 않습니다.

완료된 DINO 네 후보와 Y1~Y4를 같은 기준으로 비교했고, DINO 대표는 **EX-06 LoRA + TTA**, YOLO 대표는 **Y2 NMS + TTA**로 선택했습니다. 전체 val로 기준과 후보를 골랐으므로 점수는 **개발 val 결과**이며 독립 test 성능으로 부르지 않습니다.

### 9번 DINO와 결합 · 여기서 종료

첫 결합은 사진 전체를 보는 DINO 대표 D와 선택한 YOLO 후보 Y의 클래스별 점수 `0.5D + 0.5Y`로 고정합니다. 새 모델 학습·ROI crop·보정·가중치 탐색을 동시에 넣지 않습니다. 결합의 두 판정 기준은 따로 val에서 고릅니다. YOLO 단독·DINO 단독·결합을 모두 보고하며, 결합이 더 좋다는 결론을 미리 정하지 않습니다.

같은 파일명의 사진을 각각 추론합니다. DINO는 뒷축·밑창 sigmoid 점수 두 개, YOLO는 클래스별 최대 박스 점수 두 개를 냅니다. 예를 들어 뒷축 점수가 DINO0.8·YOLO0.6이면 평균0.7이고, 밑창 점수가 DINO0.2·YOLO0.5이면 평균0.35입니다. 이는 동작 설명용 수치이며 실제 판정 기준은 합산 val에서 따로 고릅니다. 둘 다 기준 이상이면 both, 둘 다 미만이면 normal로 판정합니다. YOLO가 찾은 부분을 잘라 DINO로 다시 학습하거나 두 모델을 함께 역전파하지 않습니다. 저장한 두 점수 CSV를 파일명·열 이름으로 맞춰 **CPU에서 결합**하므로 두 모델을 GPU에 동시에 올리지 않아도 됩니다.

헤드·TTA·결합 선택의 영향은 저장한 동일 사진 점수로 보조 검증합니다. 합산 val의 신발 group을 유지한 5-fold에서 학습 쪽 4/5로만 YOLO 후보와 판정 기준을 고르고 나머지 1/5를 예측해 합칩니다. 분할별 클래스·그룹 수가 부족하면 점수를 보기 전에 가능한 fold 수로 고정하고 기록합니다. 점수 보정·가중치 학습을 추후 추가할 때도 그 학습은 해당 평가 fold를 제외합니다. 기존 DINO·모델 설계에 전체 val을 이미 사용했으므로 이 검증도 독립 test를 대신하지 않습니다.

차이가 작으면 같은 신발 그룹의 짝지은 부트스트랩을 보조로 보고, 이득이 불확실할 때 단독 또는 적은 모델 수를 우선합니다. 최종적인 test 사용은 모델·조합·판정 기준을 고정한 뒤 별도 요청으로 진행합니다.

기존 조사에서 검토한 RF-DETR·RT-DETR 결합과 최종 test는 이번 자동 실행에 포함하지 않습니다. **9번 비교 보고서를 출력하고 GPU를 비운 뒤 종료**합니다. 팀원에게 메시지를 보내거나 팀 폴더의 실행 코드를 수정하지 않습니다.
